## Контекст

Зріз 4 (рядок roadmap «WS10», golden cases solomchaak/property-workflows-spec#40): менеджер запуску чи адміністратор
вставляє в запуску текст звернення орендаря або кошторису вендора, AI пропонує значення (телефон, опис, категорію,
терміновість; позиції й загальну суму), людина виправляє й підтверджує, і лише тоді значення зберігаються. Обмеження:

- Next.js 16.4 на Vercel Hobby: функція працює до 300 с; Server Action приймає тіло до 1 МБ.
- Модель — безкоштовна через OpenRouter, ключ — власний у кожного розробника. Ліміт безкоштовних моделей — 20
  запитів/хв і 50/день на акаунт; додаткові ключі ліміту не збільшують. Безкоштовні моделі з'являються й зникають.
- Безкоштовні ендпоінти можуть зберігати запити й навчатися на них → лише синтетичні дані (#40 — синтетичні).
- Відповідь моделі недетермінована, а CI має бути без мережі й без секретів.
- PDF поза scope (`requirements/product.md`), тож вхід — лише вставлений текст.

## Рішення

- Нові залежності (точні версії): `ai@7.0.162`, `@openrouter/ai-sdk-provider@3.1.0`, `zod@4.6.7` (раніше лише
  транзитивна, ADR 0006), `server-only@0.0.1`. `npm audit --omit=dev` — той самий набір, що на `main`, нових вразливостей
  немає.
- Виклик — `generateText` + `Output.object({ schema })`; схема zod (`src/lib/ai/schema.ts`) має стан
  `status: ok | needs_info | refused`, `kind: request | estimate`, переліки категорій і терміновості з #40; «невідоме» —
  `null`. Відповідь не за схемою — помилка, а не «майже пропозиція».
- **Правила, які можна перевірити кодом, — у коді** (`src/lib/documents/values.ts`): телефон у форму `555-0103`;
  суму позицій кошторису рахує код і сам формує попередження «items add up to X, the stated total is Y»; тексти відмови
  й приміток — константи коду за прапорцями моделі; код сам шукає в тексті інструкції для AI. Модель пропонує, код
  перевіряє й формулює.
- Чиста функція `proposeDocumentValues(text, model)` (`src/lib/ai/draft.ts`) отримує модель параметром; ключ читає лише
  `src/lib/ai/openrouter.ts` з `import "server-only"`. Змінна — `OPENROUTER_API_KEY`, без `NEXT_PUBLIC_`; без ключа
  (порожній рядок і пробіли теж) — `null` і стан «помічник недоступний».
- Ланцюжок моделей (лише `:free`): `google/gemma-4-31b-it:free` → `google/gemma-4-26b-a4b-it:free` →
  `nvidia/nemotron-3.5-super-vl:free`; `maxRetries` 1 у застосунку, 0 у живому eval.
- Людина в контурі: Server Action, що просить пропозицію, нічого не пише; запис — окрема дія «Save values» з повторною
  перевіркою ролі й значень на сервері і `insert` під RLS. Обидві дії перевіряють `getClaims()` і роль до моделі й до
  запису.
- Перевірка якості: 10 golden cases #40. Офлайн-реплей записаних відповідей (`MockLanguageModelV4`) — у `npm test`
  (CI); живий прогін — `npm run eval` вручну, зі звітом частки успіху за моделлю в `evals/reports/`.

## Розглянуті варіанти

- Покладатися на модель у правилах (сума кошторису, тексти приміток) — ні: модель на безкоштовному тарифі рахує й
  формулює нестабільно, а golden case 8 вимагає точного попередження; код дає той самий результат щоразу.
- Claude Agent SDK у функції Vercel — ні: підпроцес Claude Code (~320–342 МБ) більший за пакет функції (250 МБ), і тут
  потрібен один виклик моделі, а не агентний цикл.
- Пакет `openai` з `baseURL` OpenRouter — ні: немає валідації схемою з типізованими помилками й тестових моделей в
  одному API.
- `openrouter/free` (випадкова безкоштовна модель) — ні: результат golden cases не відтворюється.

## Наслідки

- Простіше: провайдера й модель міняємо в `src/lib/ai/models.ts`; CI не залежить від мережі та ліміту.
- Складніше: безкоштовна модель може зникнути або впертися в ліміт — інтерфейс показує «The assistant is not available
  now. Fill in the values yourself.», і людина заповнює форму вручну. Ланцюжок перевіряємо `npm run ai:models`.
- Записи `tests/fixtures/golden/recorded.json` оновлюємо (`RECORD=1 npm run eval`), коли змінюється промпт
  (`DRAFT_PROMPT_VERSION`) або схема.
