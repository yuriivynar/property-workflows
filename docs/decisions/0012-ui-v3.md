# 0012. UI v3: рух, меню користувача з темою, Urgency як властивість запуску, помилки на місці, живі оновлення

- Статус: прийнято (замінює частини ADR 0008: місце вибору «Theme» — тепер меню користувача внизу бічної панелі й
  сторінка Profile замість меню в правому верхньому куті; права картка запуску — кільце прогресу й властивості запуску.
  Палітра «Graphite & Teal», бічна панель, хлібні крихти, `BackLink`, `AuthHero` з ADR 0008 лишаються; механізм теми з
  ADR 0004 — cookie `theme` і `data-theme` на `<html>`, два однакові темні блоки — лишається; JSONB-знімки версій з ADR
  0002 — лишаються й несуть поля шаблону)
- Дата: 2026-11-26
- AC: AC-DSYS-01…08, AC-LOGIC-01…05, AC-TASK-04, AC-TASK-05, AC-TASK-16, AC-RUN-10, AC-TASK-11, AC-VENDOR-02, AC-VENDOR-18

## Контекст

Власник затвердив 26.11.2026 полотно Claude Design «Property workflows — UI v3 proposal» (дошки Main, Login, Runs, Run,
Templates, States, Mobile, Profile, ThemeOptions) і вимогу PM solomchaak/property-workflows-spec#51 (задача лише для
певної відповіді). Кольорові токени полотна — ті самі, що в DESIGN.md (Graphite & Teal): нових кольорів немає. Нове —
рух, розміщення теми, властивості запуску, стани помилок і функції поза вимогами PM. **Рішення власника 2026-11-26: питань
до PM не ставимо** — усе, чого немає у вимогах PM, фіксує цей ADR і `docs/spec-reading.md`; тести таких функцій — без AC
ID (інакше `ac:coverage` бачить ORPHAN). Тексти повідомлень і статусів з AC — дослівно; поведінка й права AC не змінюються.

## Рішення

- **Рух — токени** (`globals.css`, `@theme inline`): `--duration-fast` 120 мс (наведення, натискання, фокус),
  `--duration-base` 200 мс (зміна стану, перемикач, поява рядка), `--duration-slow` 280 мс (зміна сторінки, панель);
  крива `--ease-standard: cubic-bezier(0.2, 0, 0, 1)`. Рух лише коли щось змінює стан чи місце; `prefers-reduced-motion`
  — без руху (лише колір і прозорість; наявне правило `animation/transition: none`). Анімація — лише CSS / Web API.
- **Переходи сторінок** — React `<ViewTransition>` (React 19.3 / Next 16.4 без конфігурації, гайд
  `node_modules/next/dist/docs/01-app/02-guides/view-transitions.md`), тривалість `--duration-slow`.
- **Меню користувача з темою (варіант A полотна ThemeOptions).** Внизу бічної панелі — кнопка з аватаром, email і
  роллю → `DropdownMenu`: рядок «Theme» з трьома радіо лише з іконкою System / Light / Dark (`aria-label` і підказка
  `Tooltip` «Theme: System» тощо), далі Profile і Sign out. Окремий рядок `ThemeSwitch` над вмістом сторінки прибрано. На
  телефоні — аватар у верхній смузі → `Sheet` з темою й Sign out; нижні вкладки лишаються. Повний перемикач зі словами —
  на сторінці Profile. Тести AC-DSYS-05/06 відкривають меню або Profile, перевірки не слабшають.
- **Аватар — нейтральний**, не бірюзовий: акцент лишається лише для однієї головної дії (DESIGN.md, розділ 1; полотно
  фарбує ініціали в `primary` — свідомо відхиляємось).
- **Urgency (#51) — варіант «detail»**: властивість у правій картці деталей запуску — кнопка-меню з крапкою й рядком
  ефекту під кожною відповіддю («Adds "Send an emergency plumber" to Assessment», «No extra tasks»); прихована умовна
  задача — пунктирний рядок-«привид» у своєму розділі («Appears only when Urgency is Urgent · not counted in progress»)
  з кнопкою «Set Urgency». Відповіді **показуються** «Urgent» / «Not urgent», **зберігаються** як у тексті PM — `urgent` /
  `not urgent`. Меню й «привиди» — лише менеджеру запуску й адміністратору; виконавцю — текст відповіді; вендору — нічого.
  Варіант «cards» полотна не будуємо. Крапка «Urgent» — `destructive`, «Not urgent» — `fill-progress`; слово завжди поруч.
- **Картка деталей запуску**: кільце прогресу (SVG, анімований `stroke-dashoffset`, синє → зелене), «N of M done»,
  статус, Run manager, Template, поля запуску. Прогрес розділу «N of M done» — біля назви розділу.
- **Позначка виконаною — миттєво** (`useOptimistic`): відмова сервера повертає рядок на місці з дослівним текстом AC;
  підтвердження останньої обов'язкової задачі на місці — як зараз (AC-TASK-04, AC-TASK-16).
- **Помилки на місці.** Помилка поля — під полем, після відправлення, з іконкою, `aria-invalid` + `aria-describedby`,
  зникає, щойно поле виправлено. Помилка форми — `Alert` з коротким заголовком і дослівним текстом AC, фокус переходить
  на нього. Автозбереження редактора — в одному фіксованому місці: «All changes kept» / «Your last change was not kept.
  Try again.». Спливаючих повідомлень (toast) немає.
- **Поза вимогами PM (рішення власника 2026-11-26, тести без AC ID):** вкладки «All · In progress · Completed» з
  лічильниками і фільтр за назвою випадку (у search params) у списку запусків; рядки, що розгортаються (прогрес розділів,
  наступна задача й виконавець); сітка карток шаблонів зі станом версії; сторінка Profile (Account, Preferences, «Your
  work» з лічильниками й «Your next tasks»); фото профілю (Supabase Storage `avatars`, кожен пише лише свою теку, PNG/JPG
  до 2 МБ) — **чуже фото ніколи не показуємо** (AC-RUN-10, AC-TASK-11, AC-VENDOR-02/18 — лише email); стрічка Activity і
  живі оновлення через Supabase Realtime (`postgres_changes`, діє RLS) з індикатором «Live · updated just now»; палітра
  команд ⌘K (shadcn Command).
- **Спільний `getViewer()`** у React `cache()` — один запит профілю на рендер для макета й сторінок; `loading.tsx` для `/`,
  `templates/[id]/edit`, `templates/[id]/versions`.
- **Демо-кнопки полотна** («Simulate a teammate», «Replay the rollback», «Simulate a lost connection») — лише для
  прототипу, у застосунок не переносимо. Вхід — `AuthHero` з ADR 0008 (кнопка «Pause animation» видно лише при наведенні,
  фокусі, на паузі й на сенсорних екранах — PR #126), а не варіант полотна з «Replay».

## Наслідки

- Простіше: один набір тривалостей руху; тема — в одному місці з іншими особистими налаштуваннями; умовні задачі видно
  менеджеру навіть прихованими, тож зрозуміло, що змінить відповідь.
- Складніше: більше клієнтських компонентів (меню, `useOptimistic`); тести AC-DSYS-05/06 відкривають меню.
- Якщо PM змінить вимоги до теми чи полів — новий ADR «замінює 0012» для відповідної частини.
