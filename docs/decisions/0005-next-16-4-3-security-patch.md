# 0005. Next.js 16.4.0 → 16.4.3: патч безпеки в межах зафіксованої лінії 16.4

- Статус: прийнято
- Дата: 2026-10-28
- AC: — (безпека платформи; стосується всіх сторінок і server actions)

## Контекст

`AGENTS.md` фіксує стек («Next.js 16.4 … не оновлювати без ADR»). `npm audit` для `next@16.4.0` показує:
- GHSA-2464-fhr4-w9xw (**critical**) — віддалене виконання коду без автентифікації в Image Optimization API (SVG);
- GHSA-673q-mjm6-r5xr (**critical**) — віддалене виконання коду без автентифікації у функціях `use cache` з typed
  arrays;
- GHSA-p3m5-59mp-jv5r (**high**) — відмова в обслуговуванні в App Router через Server Actions.

Уразливі версії — `>=16.0.0 <=16.4.0` для всіх трьох, тож перша виправлена версія — `16.4.1`. Next.js блокував
локальні `next dev` і `next build` попередженням про вразливість, а продакшн на Vercel працював на уразливій версії.

## Рішення

- `next` і `eslint-config-next` — **16.4.3**, точні версії (як і раніше, без `^`).
- `package-lock.json` змінено лише в записах `next`, `@next/*` і `eslint-config-next`. Записи `@emnapi/*`, які `npm
  install` на Windows викидає, повернуто з lock-файлу `main`, і lock-файл перевірено чистим `npm ci`.
- Решту стеку (React, TypeScript, ESLint, Tailwind, Supabase) не змінюємо. Рядок «Next.js 16.4» в `AGENTS.md`
  лишається правдивим.

## Розглянуті варіанти

- **Лишити 16.4.0** — чому ні: критичні RCE в публічному застосунку, і локальна збірка заблокована.
- **`next upgrade` / найновіша версія** — чому ні: правило «не оновлювати все до latest»; потрібен лише патч безпеки.
- **16.4.1 — перша виправлена версія** — чому ні: 16.4.3 — останній патч тієї самої лінії, і саме його пропонує
  `npm audit fix`. Патчі в межах лінії містять лише виправлення, тож разом із виправленням цих трьох вразливостей беремо й решту
  виправлень лінії, а не зупиняємося на мінімально достатній версії.

## Наслідки

- Інші зауваження аудиту стосуються не застосунку, а інструментів розробки, тож лишаються окремим питанням. Це
  `shadcn` CLI (low) і транзитивний `zod` через `@fission-ai/openspec` (high).
- Наступні патчі безпеки Next.js у межах 16.4 — так само: окремий PR з цим ADR як зразком.

## Як перевіряємо

- `npm audit`: для `next` / `@next/*` вразливостей немає.
- `npm run build` проходить і показує `ƒ Proxy (Middleware)`; `lint`, `typecheck`, `npm test` — зелені; CI (`app`)
  виконує `npm ci` з цим lock-файлом.
