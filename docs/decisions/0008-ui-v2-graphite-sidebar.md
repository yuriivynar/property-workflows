# 0008. UI v2: палітра «Graphite & Teal», бічна панель, меню «Theme» у правому верхньому куті, вхід без кольорової шапки

- Статус: прийнято (замінює з ADR 0007 палітру «Lagoon», кольорову шапку з навігацією, три позначки вибору теми в шапці
  й панель входу окремою карткою; з ADR 0004 — місце вибору «Theme». Механізм теми з ADR 0004 — cookie `theme` і
  `data-theme` на `<html>`, два однакові темні блоки — лишається; шрифт IBM Plex Sans і форми з ADR 0007 лишаються)
- Дата: 2026-11-11
- AC: AC-DSYS-01, AC-DSYS-02, AC-DSYS-03, AC-DSYS-04, AC-DSYS-05, AC-DSYS-06, AC-DSYS-07, AC-VENDOR-13

## Контекст

Вимоги PM («Вигляд і тон» у `requirements/product.md`) не змінилися: один сильний акцент лише для головної дії,
статуси за змістом і завжди зі словом (to do — сірий, in progress — синій, done / completed — зелений, Unpublished
changes — теплий жовтий, помилки — червоний), контраст ≥ 4.5, щільні таблиці, світла й темна теми з вибором System /
Light / Dark; не годяться яскраві градієнти, декоративна анімація, дрібний сірий текст, іконки без підпису й спливаючі
вікна для звичайної інформації.

Розробнику Lagoon здалася дивною. Окремий субагент-рецензент пояснив чому: шапка (240°) і тло (245°) того ж відтінку,
що статус «in progress» (250°), тож увесь екран читається як один великий синій статус, а бірюзова дія з низькою
насиченістю поруч із синім виглядає брудно-зеленою. Розробник також попросив: прибрати кольорову лінію під шапкою;
на вході — лише логотип, без кольорової смуги; живішу, але легку анімацію входу того самого розміру, що й форма;
навігацію бічною панеллю; інший вигляд посилань «Back to …»; переглянути місце вибору «Theme». Прототип —
полотно Claude Design «Property workflows UI v2» (палітри поруч, вхід, Runs, запуск, телефон, вендор); розробник
затвердив його 10.11.2026.

## Рішення

- **Палітра A «Graphite & Teal».** Нейтральна графітова оболонка (hue 230, хрома ≤ 0.015): тло, картки, бічна панель;
  колір мають лише головна дія (бірюзова, hue 200 / 198) і статуси, тож статуси «звучать» найчистіше. Статусні,
  `destructive*`, `fill-*` і `hero-progress` / `hero-done` токени не змінюються — AC-DSYS-07 і
  `tests/design/status-dark-contrast.test.ts` лишаються в силі. Значення й контраст (26 пар, усі в нормі) —
  `DESIGN.md`, розділ 2; у `src/app/globals.css` — світлий блок і два однакові темні (ADR 0004).
- **Навігація — бічна панель** від `lg` (графітова, `bg-hero`): логотип, пункти з іконкою **і** словом (Templates ·
  Runs · Profile; поточний — фон і `aria-current`), внизу email і роль. На телефоні — нижні вкладки з іконкою й словом
  (цілі ≥ 44 px). У DOM **один** `<nav aria-label="Main">`, різне розміщення — лише CSS; вендору — лише Runs і Profile
  (AC-VENDOR-13, `navItems`).
- **Вибір «Theme» — компактне меню в правому верхньому куті кожної сторінки** (на вході — у рядку з логотипом, у
  застосунку — праворуч у рядку з хлібними крихтами, на телефоні — у верхній смузі). Закрите меню показує «Theme» і
  поточне значення («Theme System» — AC-DSYS-05/06), відкрите — три нативні радіокнопки System / Light / Dark з
  іконками й галочкою. Реалізація — `<details>` / `<summary>` із нативними радіо (працює з клавіатури й без JavaScript
  для відкриття); застосування в DOM і cookie — як раніше (`src/lib/theme-dom.ts`, ADR 0004). Це елемент керування, а
  не спливне вікно з інформацією.
- **Вхід без кольорової шапки.** На тлі сторінки — великий двоколірний логотип (графітова плитка зі «сходинками» і
  зеленою крапкою — колір «done»; «Property» + приглушене «workflows»). Анімація кільця процесу з ADR 0007 лишається й
  стає живішою: три точки-задачі на кільці по черзі стають зеленими, під словом-статусом — лічильник «N of 3 done»,
  наприкінці — хвиля. Панель і форма — дві половини **однієї** картки (однакова висота). Рухаються лише `transform`,
  `opacity`, `stroke-dashoffset`; рух стає на паузу, коли вкладку сховано, і кнопкою «Pause animation» (WCAG 2.2.2);
  `prefers-reduced-motion` вимикає все.
- **Логотип.** Під час завантаження сторінки «сходинки» один раз прокреслюються, крапка «вистрибує»; при наведенні або
  фокусі з клавіатури крапка стрибає сходинками вгору. Лише CSS, вимикається `prefers-reduced-motion`.
- **Посилання.** Замість «Back to …» на звичайних сторінках — хлібні крихти над заголовком («Runs › Apartment 12,
  move-in»); на відмовах і «не знайдено» текст посилань лишається дослівно («Back to runs», «Back to templates» —
  AC-DSYS-02, AC-VENDOR-08, AC-VENDOR-14), але має вигляд кнопки-контуру зі стрілкою. Рядок таблиці запусків
  клікабельний цілком (посилання на назві випадку розтягнуто на рядок), назва — без підкреслення, шеврон —
  `aria-hidden`.
- **Сторінка запуску** від `lg` — дві колонки: розділи з задачами ліворуч, закріплена картка прогресу праворуч.

## Розглянуті варіанти

- **B «Iris»** (фіолетова дія) — найяскравіша, але 300° лише на 50° від «in progress».
- **C «Plum»** (сливова дія, теплий фон) — 340° лише на 47° від червоного: дію можна сплутати з помилкою.
- **Лишити Lagoon** — відхилено за відгуком розробника.
- **«Theme» у бічній панелі чи на картці входу** — були на першому варіанті полотна; розробнику не сподобалось: на
  різних сторінках вибір опинявся в різних місцях. Одне місце (правий верхній кут) — передбачуваніше.
- **Цикл однією кнопкою System → Light → Dark** — відхилено: не видно всіх варіантів, гірше для читачів екрана.
- **Два `<nav>` (бічна панель і нижні вкладки)** — відхилено: подвоїло б посилання для читачів екрана й e2e
  (AC-VENDOR-13 рахує пункти навігації).

## Наслідки

- Реалізація — окремими PR `task/ui-*`: палітра (цей ADR, токени, `DESIGN.md`) → оболонка (бічна панель, нижні
  вкладки, меню «Theme», логотип) → вхід → хлібні крихти, рядки-посилання, дві колонки запуску. Селектори e2e
  (`data-testid`, ролі, тексти AC) не змінюються; тести вибору теми переходять на меню.
